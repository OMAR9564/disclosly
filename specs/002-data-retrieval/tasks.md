# Tasks: Phase 2 — Data + Retrieval

**Input**: Design documents from `specs/002-data-retrieval/`

**Prerequisites**: [plan.md](./plan.md), [spec.md](./spec.md), [research.md](./research.md), [data-model.md](./data-model.md), [contracts/](./contracts/), [quickstart.md](./quickstart.md)

**Tests**: REQUIRED. Constitution II (Test-First): each task ships with its own tests in the same PR. Write the tests first, see them fail, then implement. Coverage stays ≥ 80%. Network calls in tests use recorded fixtures under `tests/fixtures/`; no test downloads a model or calls KAP/SEC live.

**Organization**: Grouped by user story, in priority order (US1 → US2 → US3). US2 and US3 tests use fixture corpora, so they can be tested without a full ingestion; the full run (SC-001, SC-004) needs US1 done.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies on incomplete tasks)
- **[Story]**: User story from spec.md (US1–US3)
- **(owner action)**: Needs the owner's machines, accounts or server. An agent prepares files and docs; the owner runs it.

## Path Conventions

Paths follow plan.md "Source Code": packages `ingestion/`, `retrieval/`, `workers/`, `evals/` at the repo root; migrations in `api/migrations/versions/`; tests in `tests/unit/<package>/` and `tests/integration/<package>/`.

## Phase 4: User Story 2 — Hybrid search (Priority: P2)

**Goal**: `search_documents` and `list_documents` per [contracts/search.md](./contracts/search.md).

**Independent Test**: Against a fixture corpus loaded into Postgres, TR and EN queries with and without filters return ≤ k hits that all match the filters, each with a source ref; a no-match filter returns `[]`.

- [ ] T022 [P] [US2] Implement `retrieval/embeddings.py`: query embedding with `query: ` prefix behind the `Embedder` protocol, Redis cache key `qemb:{model}:{sha256(normalised query)}`, float32 bytes, TTL 7 days. Tests in `tests/unit/retrieval/test_embeddings.py` (cache hit avoids the embedder call)
- [ ] T023 [P] [US2] Implement `retrieval/vector.py` and `retrieval/fulltext.py`: shared filter builder from `SearchFilters` (tickers, period range via `Period` ordering, doc_types, sections, language, chunker_version) applied in SQL `WHERE`; vector top-N with `hnsw.ef_search = 80` and `hnsw.iterative_scan = relaxed_order`; full-text top-N with `ts_rank_cd`, query parsed with both `tr_unaccent` and `en_unaccent`. Integration tests in `tests/integration/retrieval/test_paths.py`: filters never violated, "favok" matches "FAVÖK"
- [ ] T024 [P] [US2] Implement `retrieval/fusion.py` (RRF, k=60, ties by `chunk_id`) and `retrieval/rerank.py` (cross-encoder behind a `Reranker` protocol, top `RETRIEVAL_RERANK_TOP`, switch `RETRIEVAL_RERANK`). Unit tests in `tests/unit/retrieval/test_fusion.py` and `test_rerank.py` with fakes
- [ ] T025 [US2] Implement `retrieval/search.py`: `SearchFilters`, `SourceRef`, `SearchHit`, `DocumentMeta` models and `search_documents(query, filters, k=6)` / `list_documents(...)` per the contract (`1 ≤ k ≤ 50`, empty query → `ValueError`, no match → `[]`, sorted by score desc then `chunk_id`); emit an OTel span and a JSON log with latency per call. Integration tests in `tests/integration/retrieval/test_search.py` covering every acceptance scenario of US2

## Implementation Strategy

1. MVP = Setup + Foundational + US1 with SEC only (T009–T015, T018): idempotent, cited corpus for US companies.
2. Add KAP (T016–T017), worker deployment (T019–T020), full run (T021).

4. US3 golden set, CI gate, sweep and ADR: phase acceptance gate.
5. One branch and one PR per tasks.md phase (e.g. `feat/phase-3-us1-ingestion`), as in Phase 1; the owner commits and opens the PR at phase end.
